# Техническое задание на доработку steamsys.ru


**Версия 0.2. Рабочий документ**

## 1. Граница документа

Дорабатывается действующий сайт на 1С-Битрикс. Существующие инфоблоки и контент сохраняются. Добавляются только недостающие свойства, связи, компоненты и шаблоны. Системное ядро 1С-Битрикс не изменяется.

Структура каталога продукции сохраняется как на действующем сайте steamsys.ru до модернизации: состав и названия разделов и подразделов, их иерархия и принадлежность товаров к разделам. Прототипы и новый дизайн не являются основанием для изменения этой структуры.

ТЗ не пересказывает то, что видно в прототипах и дизайне. Оно описывает только механику, которую нельзя увидеть: источники данных, связи, фильтры, формы, ограничения и поведение при отсутствии данных.

| Источник | За что отвечает |
|---|---|
| ТЗ | Механика, данные, связи и ограничения |
| Утверждённый прототип | Состав страницы и пользовательский сценарий |
| Утверждённый дизайн | Внешний вид, расположение и адаптивное отображение |

Если дизайн меняет прототип визуально, применяется дизайн. Если требуется изменить механику, изменение сначала вносится в ТЗ.

Не входят: смена CMS, корзина и оплата, личный кабинет, обмен с 1С/ERP, AI-ассистент и новые функции, которых нет в прототипах или этом ТЗ.

## 2. Общие правила

| Тема | Правило |
|---|---|
| Стандартные поля | Штатные Title, Description, H1, название и ЧПУ не описываются и не считаются новой функцией. |
| Новые поля | Если нужного проектного поля нет, оно добавляется к существующей сущности. Номера инфоблоков и коды свойств в ТЗ не фиксируются. |
| Пустые данные | Незаполненное необязательное поле не выводится. Если пуст весь блок, скрываются заголовок, фон, отступы, якорь и пункт локальной навигации. |
| Публикация | В связях и подборках участвуют только активные опубликованные элементы. Данные из прототипов не считаются подтверждённым контентом. |
| Связи | Связь хранится в одном месте. Обратные подборки строятся по этой же связи, без второго дублирующего поля. |
| Ручная подборка | Редактор выбирает элементы и их порядок. Если ничего не выбрано, блок скрывается, если в ТЗ не указано автоматическое заполнение. |
| Мини-карточки | В слайдер или компактную подборку загружается не более 6 карточек. |
| Похожие товары | Подбираются автоматически. Сначала берутся другие товары текущей категории. Если их меньше 6 — товары из соседних категорий с тем же родительским разделом, по сортировке каталога. Текущий товар исключается. Ручного поля нет. |
| Статьи | Редактор может выбрать конкретные статьи. Без выбора выводятся активные статьи по штатной сортировке раздела. Ручной выбор имеет приоритет. Лимит — 6. |
| Остальные рекомендации | Автоматический подбор применяется только там, где его правило прямо указано в ТЗ. |
| Фильтруемые списки | Фильтры работают совместно. Выбор, сортировка и страница сохраняются в URL. Есть общий сброс, загрузка, пустой результат и ошибка. |
| Подгрузка | Если в прототипе есть «Показать ещё», следующая порция добавляется без дублей. |
| Cookie | Используется установленный модуль. Новый баннер и новая вёрстка не создаются. Проверяется только совместимость с новыми шаблонами. |
| Формы | Используются готовые формы Битрикс24. Сайт размещает скрипт, стилизует форму и передаёт контекст. Собственный обработчик заявок не создаётся. |

### 2.1. Новые функциональные поля

**Референс фильтра каталога**

За основу фильтра каталога продукции принимается фильтр на странице [ADL «Конденсатоотводчики»](https://adl.ru/truboprovodnaya-armatura/kondensatootvodchiki/) (дата проверки: 24.09.2026). Используются группировка параметров, диапазоны числовых значений, раскрытие длинных списков значений и действия применения и сброса фильтра. Внешнее оформление адаптируется к утверждённому дизайну steamsys.ru.

Для конденсатоотводчиков референс задаёт параметры: бренд, DN, PN, тип присоединения, материал корпуса, максимальная температура рабочей среды и тип механизма. Параметры выводятся при наличии соответствующих данных у товаров. Для остальных категорий состав фильтра определяется их характеристиками; тип и среда сохраняются там, где применимы и заполнены. Значения и границы диапазонов берутся из каталога steamsys.ru. Сохранение состояния в URL и состояния выдачи подчиняются общим правилам раздела 2.

## 5. Формы Битрикс24

| Правило | Требование |
|---|---|
| Размещение | Используется предоставленный скрипт Б24: внутри страницы или в модальном окне по прототипу. |
| Оформление | Форма стилизуется под утверждённый дизайн, включая поля, ошибки, кнопку и адаптив. |
| Контекст | Передаются URL и название страницы, код кнопки, идентификатор и название сущности, исходные UTM и выбранные параметры, если форма их поддерживает. |
| Проверка | Обязательность, файлы, антиспам и создание заявки настраиваются в Б24. |
| Успех | Заявка и аналитическое событие фиксируются только после сигнала Б24 об успешной отправке и только один раз. |
| Ошибка | Нельзя показывать ложный успех. Ошибка формы не должна ломать остальную страницу. |
| Данные | Имя, телефон, email, комментарии и содержимое файлов не передаются в аналитику или URL. |

Основные сценарии: консультация, подбор, запрос КП, запрос документа/CAD, отправка параметров, онлайн-опросный лист, отклик на вакансию и общий вопрос сотруднику.

## 6. SEO и аналитика

| Тема | Требование |
|---|---|
| Canonical | У индексируемой страницы один абсолютный canonical. Можно задать другое значение для согласованного дубля. |
| Open Graph | Настраиваются заголовок, описание и изображение. URL берётся из canonical. Если поле пусто, используются обычные данные страницы. |
| Модуль | Для canonical и Open Graph можно использовать совместимый модуль Marketplace 1С-Битрикс. |
| Редиректы | При изменении адреса старый URL получает один 301 на смысловую замену. Незатронутые адреса не меняются. |
| Фильтры | Страницы с параметрами не индексируются, если SEO-специалист отдельно не утвердил посадочную страницу. |
| Разметка | Данные для поисковиков добавляются только по видимому и подтверждённому содержимому. |
| Формы | Цель отправляется после сигнала Б24 об успешной отправке, а не после клика по кнопке. |
| Файлы | Событие отправляется после начала скачивания рабочего файла. |
| Калькулятор | Событие отправляется после получения корректного результата. |
| Контакты | Событие отправляется при клике по ссылке телефона или email. |
| Персональные данные | В аналитику не передаются. |

## 7. Общая приёмка

Работа считается готовой, если:

1. состав и внешний вид соответствуют утверждённым прототипам и дизайну;
2. данные берутся из указанных сущностей, а примеры из прототипа не зашиты в шаблон;
3. ручные связи редактируются, автоматические работают по правилам ТЗ;
4. пустые поля и блоки не создают пустую вёрстку;
5. фильтры, пагинация, подгрузка, галереи, модальные окна и калькуляторы имеют рабочие состояния;
6. формы создают ожидаемый результат в Б24 и передают контекст страницы;
7. на компьютере, планшете и телефоне нет перекрытий и горизонтальной прокрутки всей страницы;
8. интерактивные элементы работают мышью, касанием и клавиатурой;
9. canonical, Open Graph, редиректы и события аналитики проходят проверку;
10. на опубликованном сайте нет навигатора прототипов, тестовых обработчиков, `href="#"` и ссылок на локальные HTML-файлы.
11. структура каталога соответствует действующему сайту до модернизации: сохранены состав и названия разделов и подразделов, иерархия и принадлежность товаров;
12. фильтр каталога реализован по референсу ADL и требованиям раздела 4.3; параметры и значения соответствуют данным текущей категории, применение и сброс работают.
